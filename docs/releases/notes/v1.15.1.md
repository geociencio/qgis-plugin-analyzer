# v1.15.1: Security Scanning Restored 🔐

Patch release. It fixes a **silent security regression**: the Bandit-inspired
checks were never registered, so the analyzer reported a clean security score
while detecting nothing. It also lands the post-1.15.0 hardening (dead-code
removal, complexity reductions and a big coverage boost).

## Fixed

- **Security registry restored.** `security_rules` was never imported, so
  `SecurityRegistry` stayed empty and **no** AST security check executed. The
  analyzer (and `qgis-plugin-manager`, which delegates to it) reported zero
  vulnerabilities even for `eval`/`exec`, unsafe `pickle`, `shell=True`, SQL
  injection and hardcoded secrets. The checks now register on import, a
  regression test guards it, and the `security` scope lists the real rule ids
  (`B102`, `B301`, `B307`, `B602`, `B608`, `HARDCODED_SECRET`).

## Changed

- **Single source of truth for scopes**: `rules/scopes.py` is now shared by the
  engine's issue filtering and the visitors' reporting gate.
- **Dead code removed**: `models/` package, `rules/modernization_rules`,
  `FixRegistry.get_all_handlers`, `BaseCommand.setup_output_dir` and the unused
  package-size/binary helpers in `validators`.
- **Complexity reduced**: `ProjectAnalyzer.run` (16→1),
  `StandardsVisitor.visit_For` (18→1), `I18nVisitor.visit_Constant` (17→8).
- **Coverage 75% → 86%**; CI coverage floor raised to **80%**.

## Docs

- Deep-updated `README.md` (features, CI badge, CLI and report contract) and
  moved the alternatives comparison to an internal doc.

## Upgrade notes

- No breaking changes to rule ids or the CLI. Upgrade is drop-in; if you relied
  on the previous (empty) security results, expect real findings now.
