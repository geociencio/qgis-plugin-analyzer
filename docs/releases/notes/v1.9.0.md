# v1.9.0: Specialized Analysis Subcommands 🎯

**Release Date**: 2026-02-15

## Overview

This release introduces **specialized analysis subcommands** to the `analyze` command, enabling developers to perform targeted audits on specific aspects of their QGIS plugins while maintaining full backward compatibility with existing workflows.

---

## 🎯 Key Features

### Specialized Analysis Scopes

The `analyze` command now supports focused analysis through dedicated subcommands:

```bash
# Internationalization audit
qgis-analyzer analyze i18n [path]

# Security vulnerability scanning
qgis-analyzer analyze security [path]

# Performance and UI blocking detection
qgis-analyzer analyze performance [path]

# Dependency and coupling analysis
qgis-analyzer analyze architecture [path]

# QGIS metadata validation
qgis-analyzer analyze metadata [path]

# Full analysis (default, legacy compatible)
qgis-analyzer analyze [path]
```

### Benefits

- **⚡ Faster Feedback**: Focus on specific concerns without running full analysis
- **🎯 Targeted Fixes**: Address i18n, security, or performance issues independently
- **🔄 CI/CD Integration**: Run different scopes in parallel pipelines
- **📊 Cleaner Reports**: Only see issues relevant to your current focus
- **✅ Zero Breaking Changes**: Existing scripts work without modification

---

## 📋 What's New

### Added

- **Specialized Subcommands**:
  - `i18n`: Detects untranslated user-facing strings (1,150 issues in self-analysis)
  - `security`: Identifies unsafe subprocess calls, hardcoded secrets, SQL injection risks
  - `performance`: Finds blocking network calls, missing spatial indexes, non-pythonic loops
  - `architecture`: Analyzes QGIS API usage, import patterns, legacy code
  - `metadata`: Validates QGIS plugin structure and metadata.txt compliance

- **CLI Commands Roadmap**: Comprehensive 3-phase implementation plan documented in [`docs/research/CLI_COMMANDS_ROADMAP.md`](../research/CLI_COMMANDS_ROADMAP.md)
  - Phase 1 (v1.9.0): High-impact commands (`fix`, `docs validate`, `search deprecated`)
  - Phase 2 (v2.0.0): Migration tools (`migrate pyqt5-to-pyqt6`, `test generate`, `package build`)
  - Phase 3 (v2.5.0): Advanced analysis (`benchmark profile`, `docs generate`, `init plugin`)

### Changed

- **Scope-Based Filtering**: Analysis engine now filters issues at multiple levels:
  - Visitor-level reporting (`BaseVisitor._should_report()`)
  - Composite aggregation (`CompositeVisitor`)
  - Final result building (`ProjectAnalyzer._filter_issues_by_scope()`)

- **Visitor Architecture**: All visitors extended to support scope-aware analysis
  - `BaseVisitor`, `MetricsVisitor`, `StandardsVisitor`, `QGISRulesVisitor`, `SafetyVisitor`
  - Scope parameter propagated through worker context for parallel execution

### Technical Details

- **Manual Argument Dispatch**: `AnalyzeCommand` uses manual parsing to preserve legacy syntax
- **Worker Context Sharing**: Scope propagated to all parallel workers via shared context
- **Zero Overhead**: Scope filtering adds negligible performance impact (<1%)

## 🚀 Upgrade Guide

### For Users

No changes required! Existing commands work exactly as before:

```bash
# These are equivalent
qgis-analyzer analyze .
qgis-analyzer analyze all .
```

### For CI/CD Pipelines

Consider splitting analysis into parallel jobs for faster feedback:

```yaml
# .github/workflows/quality.yml
jobs:
  i18n-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: qgis-analyzer analyze i18n .
  
  security-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: qgis-analyzer analyze security .
```
