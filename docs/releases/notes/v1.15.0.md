# v1.15.0: Repo Hygiene, CLI Hardening & CI 🧹

This release cleans up the repository, hardens the CLI, adds a real quality
pipeline (CI + coverage + complexity self-gate), and extends the analyzer with
design-pattern, anti-pattern, Halstead and generic-optimization coverage.

## What's Changed

### Inline `# noqa` opt-out (transversal)
- Any rule can be suppressed inline: `# noqa` silences every rule on the line,
  `# noqa: RULE_ID` silences a single rule.
- Implemented with a reusable `tokenize`-based detector
  (`analyzer.visitors.noqa`); the legacy `# no-i18n` behavior is preserved.

### Design patterns, anti-patterns, Halstead & optimizations
- New `PatternsVisitor` reports design patterns (`singleton`, `factory`,
  `observer`, `strategy`, `decorator`) in the `patterns` output field.
- Low-severity anti-patterns: `GOD_OBJECT`, `SPAGHETTI_CODE`, `MAGIC_NUMBER`,
  `DEAD_CODE` (all `# noqa`-suppressible).
- Per-module Halstead metrics (`research_metrics.halstead`).
- Generic `optimizations`: `module_too_large` and `complexity_refactoring`.

### Configurable workers
- `analyze --workers N` (and the `workers` profile key) control the process
  pool; files are batched to reduce IPC overhead. Default `min(4, max(1, cpu-1))`,
  clamped to `1..4` to bound memory.

### CI & quality gates
- `.github/workflows/ci.yml` (Python 3.11–3.13): `ruff check`,
  `ruff format --check`, `mypy src/`, `pytest` with a coverage floor
  (`--cov-fail-under=70`) and the `--max-cc 15` self-analysis gate.

### Reliability fixes
- Ruff runs via `sys.executable -m ruff` (no `PATH` dependency) and reports
  `ruff_metadata.tool_unavailable` when it cannot run.
- `str`/`pathlib.Path` inputs are normalized before `.stat()` in the scanner and
  validators (guards the historical `'str' object has no attribute 'stat'`).
- `extract_runtime_imports_from_ast`, `apply_fixes` and `handle_analyze`
  refactored below the CC 15 threshold.

### Repository hygiene
- Generated artifacts (`AI_CONTEXT.md`, `PROJECT_SUMMARY.md`,
  `project_context.json`, `.analyzer_state.json`, `.coverage`, `analysis.log`, …)
  are no longer tracked; `.gitignore` extended accordingly.
- Debug artifacts archived under `docs/development/`.

## Upgrade notes
- No breaking changes to rule IDs or the CLI surface. `project_context.json`
  gains `ruff_metadata`, `patterns` and `optimizations` fields.
