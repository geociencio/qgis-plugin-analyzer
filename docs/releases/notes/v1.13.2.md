# v1.13.2: I18n False Positive Fix 🌐

This patch release fixes a significant false positive issue in the i18n checker. The analyzer now correctly recognizes `QCoreApplication.translate()` as a valid Qt i18n wrapper, eliminating ~80% of false positive `MISSING_I18N` flags in projects using the standard Qt translation API.

## What's Changed

- **I18n Wrapper Recognition**: The `I18nVisitor` now treats `tr()` and `translate()` calls as recognized i18n wrappers. Strings inside these calls are no longer flagged as untranslated.
- **Extended Coverage**: `QCoreApplication.translate("Context", "...")` and `QObject.translate("Context", "...")` are now recognized alongside `self.tr("...")`.
- **State Tracking**: Added `_in_i18n_wrapper` flag to the visitor, mirroring the existing `_in_ignored_call` pattern.
- **Edge Cases Handled**: Format chains (`translate(...).format(...)`) and nested helper calls inside translate() correctly skip false positives.
- **11 New Test Cases**: Comprehensive tests covering static methods, `super().__init__()` chains, non-QObject classes, format chains, and nesting scenarios.
- **Agentic System Gen 6**: Internal `.agent/` system upgraded with observability (`sync_metrics.py`), 3-tier memory lifecycle, and CodeWhale runtime bridge.
