# Roadmap: Future Improvements & Optimizations

This document outlines the strategic areas for improving the **QGIS Plugin Analyzer** beyond basic linting and scoring fixes.

## 1. Engine & Performance Optimizations
- [ ] **Single-Pass AST Traversal**: Refactor `CompositeVisitor` to perform a single traversal of the AST tree, dispatching nodes to sub-visitors using a subscription/hook model instead of multiple `visit()` calls.
- [ ] **Worker Context Reuse**: Optimize `analyze_module_worker` to reuse heavyweight objects (like `SecretScanner` patterns or rule configurations) across parallel processes.
- [ ] **Subprocess Pooling**: If `ruff` is called many times, consider using a persistent process or batching file paths.

## 2. Advanced Code Metrics
- [ ] **Cognitive Complexity (CC2)**: Implement or integrate Cognitive Complexity (Sonar-style) to better reflect human readability compared to standard McCabe complexity.
- [ ] **Module Instability ($I$)**: Calculate the instability metric ($I = FanOut / (FanIn + FanOut)$). This helps identify modules that are "too coupled" and hard to maintain.
- [ ] **Project-Level Complexity Heatmap**: Generate a stats summary that highlights the "hottest" modules (high complexity + high coupling).

## 3. QGIS Standards & Best Practices (QGIS-specific)
- [x] **Thread Safety Audit (`QgsTask`)**: Detect long-running loops (e.g., intensive `getFeatures()` or `requests`) that are *not* wrapped in a `QgsTask`, which can freeze the QGIS UI.
- [x] **Signal/Slot Leak Detection**: Automatically verify that signals connected in `plugin.initGui()` are properly disconnected in `plugin.unload()`.
- [ ] **Layer Registry Audit**: Check for `QgsProject.instance().addMapLayer()` calls that might be missing proper cleanup or causing side effects in long-lived plugins.
- [ ] **Resource Usage Tracking**: Improve the reporting of *where* missing resources (from `semantic.py`) are used, including `.ui` and `.qml` file scanning.

## 4. Reporting & UX Enhancements
- [x] **Dependency Graph Visualization**: Generate a `dependency_graph.mmd` (Mermaid) or `.dot` file to allow users to visualize their plugin architecture.
- [ ] **Interactive HTML Reports**: Update the HTML reporter with sortable tables, collapsible code snippets, and a dashboard-style overview.
- [ ] **Rich Terminal Output**: Use block characters (░▒▓█) to create progress bars or distribution charts directly in the terminal for better visual feedback.
